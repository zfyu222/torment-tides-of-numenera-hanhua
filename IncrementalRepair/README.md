# v1.3反馈的专项增量修复

本目录只服务本游戏此次反馈，不修改工作区共用流水线。目标是“审现有术语 → 计算实际变化 → 自动定位句子 → 只翻译和审校影响范围”，不重做提取、试译或全文正文/审校。

## 范围

- 术语：复核已有characters/terms共5,579项，排除普通词，确认专名/游戏词、required/reference、适用范围和明显不当译名；已有专名没有确证错误就保留。6,565项运行保护沿用已通过的冻结版本，不冒充重新审校过。
- 差异：比较收录/移除、译名、遵守等级和实际匹配范围；默认required补齐为显式required、默认text补齐、term_kind/term_reason补录、出处/备注/编号变化不自动派正文。先用差异词作候选筛选，再比较完整新旧词表实际匹配，保留词边界、最长匹配和嵌套术语规则。
- 正文：只向API发送受影响记录的完整原文、资源元数据和新词表，不提供旧正文译文；另一次独立请求审校生成的新译文，要求完整六维、出处和修改证据。正确且不受影响的文本不调用API。
- 第3项：本地扫描全部70,163条，当前找到8处隐藏`{Female}/{Male}`标记新增独占括号。仅给这些已证实隐藏的标记提出去包装建议，保留标记本身；不删源文自带括号、不推定`{0}`等可见值为空。建议仍进入小范围独立审校。
- 第4项：只处理已定位的4147、4257两条分支，按完整原文和ID绑定，独立审校最小修订；不发起全游戏常识筛查。

本轮以已发布、已经冻结的词条为审校对象；旧提取候选投票/任务轨迹在`old_glossary.json`完整保存，不将已处理完的历史提案及其大量重复出处再当作待裁决候选发送。模型仍收到当前词条、两条代表原文和最多两条全文定义，原文完整、不截断。此处是本项目增量复核，并不改动共用的首次术语审校规则。

## 停止与恢复

同一工作目录有进程锁，禁止并发启动两份。连接/断流按共用规则有限重试，503/认证/余额等服务故障停止新派发，已在途响应正常保留。所有尝试都记账，服务故障不占用模型请求次数；用量未报告时保持未知。累计上限同时计入原项目既有请求和本专项新增模型请求；不清零旧账、已用次数或已成功结果。

进程异常终止后，确认原进程退出，再运行`recover-stopped`。程序检查原PID、保留未知请求账目，优先收集已保存原始回复，未收到回复的用量不猜零。然后接续原阶段。`reprepare-unissued-terms`仅用于尚未有请求/通过结果的准备视图调整，会保留旧快照；绝不重写已经请求过的输入来刷新预算。
